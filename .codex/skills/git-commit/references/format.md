# Conventional Commits format

## Structure

```text
<type>[optional scope]: <description>

[optional body]

[optional footer]
```

## Notes

- `type` is required
- `scope` is optional and should be short
- keep the description short and imperative
- make the description concrete enough that it does not read like a placeholder
- prefer naming the exact thing changed over broad words like `project`, `stuff`, `code`, or `docs`
- avoid generic verbs like `update`, `improve`, `adjust`, or `clean up` unless the object is specific
